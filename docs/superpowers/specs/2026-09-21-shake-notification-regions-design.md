# 揺れ検知通知の細分化地域設定

状態: 2026-09-21にユーザー承認済み。アプリ・バックエンドの実装は未着手。

## 目的

デバッグ画面から揺れ検知の通知条件を編集できるようにする。
地域指定は気象庁の地震情報用細分化地域に統一し、現在地と全国も選べるようにする。
将来は同じ設定画面を通常の通知設定から開く。
観測点マスターの配布は Asset Pack に統一する。

## 既存実装からの変更

- `sub_region_id` は観測点の UUID であり、細分化地域コードとして使わない。
- 市区町村コードを観測点コードと照合する現在地更新処理を廃止する。
- 対象の種類を明示し、地域未指定を暗黙に全国へ変換しない。
- 現在地の判定は EEW・地震情報と同じ `device_location.region_id` を参照する。
- 既存の `kyoshin_observation_points.json` は観測点コードと `region_code`、
  `prefecture_code` を持つ。名称・都道府県別の地域一覧は `earthquake_stations.json` を使う。

## 構成の選択

推奨は、揺れ検知専用の設定を維持し、他の通知と同じ対象種別を採用する方式。
EEW・地震情報の設定を編集せずに、デバッグ画面で揺れ検知の条件を変更できる。
将来の通常設定への移動は、画面への入口を追加することで対応する。

共通通知スロットに揺れ検知の項目を追加する方式も考えられるが、既存の
市区町村指定・プリセット・契約プランの地域枠への影響が大きいため今回は採用しない。
細分化地域を複数の観測点設定へ展開する方式は、観測点の増減に追従できないため採用しない。

## 設定契約

各条件に `target_type`、`region_code`、`enabled`、`min_level` を持たせる。
地域コードは地震情報用細分化地域の3桁文字列とし、EEW用の別コード体系と混同しない。

| target_type | region_code | 制約と判定 |
| --- | --- | --- |
| current_location | null | 端末ごとに1件。保存された現在地の細分化地域で判定 |
| nationwide | null | 端末ごとに1件。イベント全体のレベルで判定 |
| region | 必須 | 同じ細分化地域は1件。その地域の最大レベルで判定 |

`min_level` は既存の5段階を使用する。無効化してもレベルの選択値は保持する。
複数条件は OR とし、一度のイベント更新では端末へ通常通知を1件だけ送る。
都道府県は地域選択の分類に使用し、都道府県全体・市区町村・観測点を通知条件にはしない。
新たな課金制約や既存通知の地域枠との共有は追加しない。

既存の GET / PUT 設定APIをこの契約へ変更する。PUT の一括更新はトランザクションで行う。
無効な地域コード、対象種別との矛盾、重複条件、旧形式の書き込みは400で拒否し、
保存済み設定を変更しない。未知の旧フィールドを無視して全国設定として受理しない。
`GET .../shake-detection/sub-regions` は廃止し、観測点マスターを返さない。
OpenAPI と Dart クライアントは生成元から再生成する。

## Asset Pack

観測点と行政地域の対応を提供する正本は既存の Asset Pack とする。
アプリは既存の Parameter Repository を通じて、検証済みの同梱・更新済み Pack を読む。
バックエンドも同じ Pack 由来の観測点・地域名称データを読み、マスターAPIは参照しない。
今回の要件で同等の観測点ファイルを新設しない。

観測点の `region_code` ごとに、そのイベントに含まれる有効な震度の最大値を集計する。
地域不明・震度欠測の観測点から地域の震度を捏造しない。
名前解決も同じ地域コード体系を使い、観測点の自由記述地域名を細分化地域名に代用しない。
マスターが利用できない場合は地域選択をエラー・再試行表示にし、保存済み条件は保持する。
バックエンドのデータ未ロード・参照不整合は監視可能にし、地域条件を全国に拡大しない。

## 現在地と位置同期

現在地条件には固定の地域コードを保存しない。通知判定時にサーバーの最新位置を参照する。
位置が未登録・失効済みの場合、その現在地条件は不一致とする。全国条件は独立して判定する。
アプリでは「現在地を取得できていません」と権限・取得状態を表示する。

現在地条件を有効にしたとき、既存の位置権限フローと位置監視を使って初回同期を要求する。
位置更新は既存の Device Location API と headless consumer に集約する。
揺れ検知用の設定全件 PUT を位置更新のたびに実行する経路を削除する。

現在地を使う既存通知、または揺れ検知の現在地条件が有効なら、位置送信を有効にする。
どちらかの設定取得に失敗した場合、未初期化を無効と同一視しない。
既知の有効条件があれば同期を継続し、両方の無効が確認できたときだけ停止する。
この判断は位置監視と headless 用の永続状態で共有し、一方の設定保存が他方を上書きしない。
既存の pending update、acknowledgment、認証スコープ、再試行の契約を維持する。

## 通知の判定と文面

登録地域と現在地について、各条件の最低レベルを満たした細分化地域だけを候補とする。
タイトルには候補の最大レベルと、そのレベルに達した地域名をすべて列挙する。
同じ地域が現在地と登録地域の両方に一致しても重複表示しない。
同順位の地域はコード順とし、実数の震度差で同じ検知レベルの地域を除外しない。

全国条件だけに一致した場合は、全検知地域の最高レベルの細分化地域をタイトルに使う。
全国と地域条件の両方に一致した場合は、登録地域・現在地に一致した候補をタイトルで優先する。
全国のイベントレベルはあるが地域を解決できない場合、タイトルは
「{イベントの最大レベル}揺れを検知」とし、地域名を補わない。

本文はどの条件で配信されても、イベントの検知観測点が属する都道府県の一覧と、
イベント全体の最大レベルを使用する。時刻は既存と同じイベント発生時刻の日本時間とする。
都道府県はコードで重複排除してコード順に並べ、5件を超える場合は既存の「など」を使う。
都道府県を一件も解決できない場合も、名前を捏造せず地域節を省略した本文を使う。
日本語・英語・中国語の通知テンプレートを同じ契約に揃える。

例: 登録した千葉県北西部と東京都23区がともに Medium、イベント全体は Strong の場合。

- タイトル: 「千葉県北西部 東京都23区でやや強い揺れを検知」
- 本文: 「12:34頃、千葉県 東京都 神奈川県で強い揺れを検知しました」

地域ごとに通知済みレベルを管理し、初回の条件一致と、その地域のレベル上昇を再通知対象とする。
全国条件はイベント全体の通知済みレベルで管理する。
別地域の初回一致や局所的なレベル上昇を、既通知のイベント全体レベルで抑止しない。
同一レベルの反復更新、低下、名称・有効期限のみの変化では再通知しない。
イベント統合時は同じ対象の通知済み最大レベルを引き継ぎ、重複通知を防ぐ。
EEWに対応付いたイベントの通知抑制と、送信キュー・再試行の仕組みは維持する。
通常通知の改善を理由に、別契約の Live Activity の判定や表示を暗黙に変更しない。

## アプリの画面

デバッグ画面に「揺れ検知の通知設定」を追加する。
既存通知設定配下に画面・Repository・Actionを置き、デバッグメニューは入口だけを持つ。
現在地と全国には有効スイッチと最低レベルを用意する。
任意地域は「都道府県 → 細分化地域」で追加し、条件ごとに有効・無効、最低レベル、削除を編集する。
観測点選択と市区町村選択は出さない。都道府県の一括通知スイッチも設けない。
保存中の競合操作を防ぎ、保存失敗時は既存条件を失わず再試行できるようにする。
デバッグ利用者が機能フラグによって入口から追い返されないようにルートを整理する。

## 旧設定の移行と配布

旧現在地条件は現在地へ、地域指定がなく現在地でもない条件は全国へ移す。
旧観測点・市区町村・都道府県条件は、勝手に対象範囲を広げて有効化しない。
元データを保存したうえで再設定が必要な旧条件として扱い、新契約での通知判定から除外する。
アプリは対象端末へ再設定の案内を表示し、利用者が新条件を保存した後に案内を解消する。
移行の再実行で重複や意図しない有効化が起きないようにする。

DB変更、API・resolver、再生成済みクライアントの順に依存関係を管理する。
旧アプリによる旧形式の PUT は400、廃止マスターAPIは410とし、旧画面には取得失敗が表示される。
旧形式の設定書き込みを許可し続ける互換処理は設けない。
展開前に旧契約の利用状況と移行件数を確認する。実装PRと実環境への適用を区別する。

## 検証と完了条件

- API: 対象種別・地域コード・重複の検証、全件更新の原子性、旧形式の拒否と既存設定保持。
- 移行: 現在地・全国の変換、旧地域条件の保持と再設定案内、再実行、ロールバック可能性。
- resolver: 地域内最大値、閾値境界、欠測、現在地未登録、移動後、全国単独、複数条件の一致。
- 再通知: 地域だけの上昇、新地域の初回一致、同レベル反復、低下、イベント統合、配信再試行。
- 文面: 同率地域の列挙、登録地域優先、タイトルと本文のレベル差、重複排除、欠損、3言語。
- アプリ: 観測点マスターAPIを呼ばないこと、Asset Packの選択階層、保存失敗と状態保持。
- 位置同期: 揺れ検知のみ有効、既存通知のみ有効、両方有効、一方の削除・取得失敗、headless送信。
- 既存 EEW・地震情報・Live Activity の関連テスト、Dart解析、生成物とOpenAPIの整合性。
- 実機: デバッグ画面、権限、OS終了後の移動、APNs／FCMのタイトル・本文を確認する。

実機検証ができない項目は未検証として TODO に残し、ユニットテスト成功と区別する。

## PR の提出先

アプリは `YumNumm/EQMonitor`、バックエンドは `YumNumm/eqmonitor-backend` に提出する。
C# の変更が必要になった場合は `YumNumm/KyoshinEewViewer` のみに提出し、
`gh pr create --repo YumNumm/KyoshinEewViewer` と明示する。upstreamへは提出しない。
現時点の設計では、既存の観測点コード送信とバックエンドの地域コード補完を利用するため、
C# の変更は予定していない。
