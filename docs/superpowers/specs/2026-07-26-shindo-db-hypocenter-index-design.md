# 震度データベース複数震源 Index 表示設計

## 背景

地震履歴詳細ページでは、震度データベースのカタログに複数の震源が含まれる場合がある。詳細カードは代表震源を先頭にし、後続の震源を「震源 2」「震源 3」のように表示する一方、現行の詳細マップは防災情報 XML の単一震源だけを表示している。

震度データベース表示中は、カタログに含まれる座標付き震源をすべて地図へ表示し、複数震源の場合に限って詳細カードと対応する Index を付ける。

## 目的

- 震度データベース表示中に、座標を持つ全震源を地図へ表示する。
- 複数震源では、各震源マーカーに詳細カードと対応する1始まりの Index を表示する。
- 震源が1件だけの場合と防災情報 XML 表示では Index を表示しない。
- マーカー、初期カメラ、全体表示の対象震源を同じ解決結果から生成する。

## 対象外

- 詳細カードのレイアウトや文言の変更
- 防災情報 XML に複数震源の概念を追加すること
- 震源を選択したときのポップアップや詳細表示
- Index 付き画像アセットの追加や動的な画像生成
- 震源データ欠損時に別ソースの座標へフォールバックすること

## 表示対象と並び順

震度データベース表示では、`EarthquakeCatalog.hypocenters` を次の順序へ正規化する。

1. `seq == 0` の震源を代表震源として先頭にする。
2. `seq == 0` が存在しない場合は、カタログの先頭を代表震源にする。
3. 代表震源と同じ `seq` を持つレコードを除き、残りを元のカタログ順で後ろへ並べる。
4. 正規化後の位置に基づき、代表震源を `1`、残りを `2`、`3`、…とする。

Index は座標欠損レコードを除外する前に決める。これにより、地図上の Index は詳細カードの「震源 2」「震源 3」と常に対応する。緯度または経度が欠ける震源は地図へ表示しないが、後続震源の Index を詰めない。

カタログ全体の正規化結果が1件の場合は、その震源の Index ラベルを空にする。複数件ある場合は、地図へ表示できる各震源に割り当て済みの Index を表示する。したがって、複数震源の一部が座標欠損の場合、地図上に見えるマーカーが1件でも Index を表示することがある。

防災情報 XML 表示では `Earthquake.hypocenter` の座標だけを対象にし、Index は付けない。震度データベース側に有効な座標がない場合も XML 座標へフォールバックしない。

## アーキテクチャ

表示対象の決定を Widget や GeoJSON 生成から分離し、震源表示ポイントを解決する専用クラスを Data 層へ置く。解決結果の各要素は、座標と任意の Index を保持する小さなアプリ内モデルとする。

解決クラスは `Earthquake` と `showingDb` を受け取り、表示順を保持した震源表示ポイントのリストを返す。震度データベースでは前節の正規化と座標フィルタを行い、防災情報 XML では単一座標・Indexなしのリストを返す。

詳細マップ Widget は解決処理を1回だけ行い、同じリストを次の3箇所へ渡す。

- 震源マーカーレイヤーの GeoJSON
- 初期カメラの中心とズーム
- 全体表示時の bounds 計算

これにより、地図に表示していない震源をカメラだけが参照する不整合を防ぐ。

## MapLibre レイヤー

既存の震源用 `SymbolStyleLayer` を維持し、アイコンとテキストを同じ Point Feature から描画する。レイヤーを追加で分割せず、既存の source・image・layer ライフサイクルを増やさない。

GeoJSON の各 Feature は、震源座標に加えて `indexLabel` プロパティを持つ。Index を表示しない場合は空文字列とする。Symbol の `text-field` は `indexLabel` を参照する。

Index は震源記号と重ならない上側へ配置し、白文字と黒い halo を使用する。アイコンと同様に重なりを許可し、複数震源が近接していても Index 自体を collision detection で消さない。`HypocenterDisplayMode.zoomFade` では、文字の opacity もアイコンと同じ式にして、薄くなったアイコンから Index だけが浮かないようにする。

source の GeoJSON 更新と image・source・layer の初期化は分離したまま維持する。XML と震度データベースの切り替え、または震源リストの変化では固定 ID の source 内容だけを更新し、同じ image ID や source ID を再登録しない。

## データ欠損とエラー処理

- 緯度・経度の片方でも欠ける震源は Feature を生成しない。
- 数値を固定値やランダム値で補完しない。
- 表示対象が0件の場合は空の FeatureCollection を生成する。
- 表示対象が0件でもマップ全体は利用可能なままにし、既存の既定カメラ動作を維持する。
- source 更新中に Widget が破棄された場合は、既存のライフサイクルトークンと操作キューで後続操作を中止する。

## テスト方針

### 表示対象解決

- 代表震源を先頭にして1始まりの Index を割り当てる。
- `seq == 0` がない場合は先頭を代表震源にする。
- 単一の震度DB震源では Index を付けない。
- 座標欠損を除外しても、後続震源の Index を詰めない。
- XML表示は単一震源・Indexなしとする。
- 震度DBに有効座標がなくても XML 座標へフォールバックしない。

### GeoJSON と Symbol

- 全表示ポイントを Point Feature へ変換する。
- `indexLabel` が GeoJSON properties に保持される。
- Symbol が震源画像と `indexLabel` の両方を参照する。
- text の位置、色、halo、overlap、opacity が設計どおりである。

### カメラとライフサイクル

- 初期カメラが解決済み震源ポイントの先頭を使う。
- 全体表示の bounds にすべての表示可能な震源を含める。
- source 内容の変更で image・sourceを再登録しない。
- XML、複数震源DB、単一震源DBの切り替え後も固定 ID のレイヤーが維持される。

## 完了条件

- 震度データベースに複数震源がある場合、座標付きの全震源と対応する Index が地図上に表示される。
- Index は詳細カードと対応し、座標欠損があっても番号がずれない。
- 震度データベースの震源が1件の場合、Index は表示されない。
- 防災情報 XML 表示の見た目と挙動は変わらない。
- 対象テスト、Flutter analyze、差分チェックが成功する。
