# 地域選択UIの共通化と震央地名フィルター

状態: 承認済み。地域も単一／複数選択を呼び出し元で切り替えられることを追加。

## 目的と範囲

都道府県・細分化地域・市区町村の選択を、共通の検索・地図・選択確認UIへ集約する。
通知登録、ホーム指定地域、地震履歴、ホーム画面ウィジェットにある重複実装を削除する。
地震履歴へ震央地名による絞り込みを追加する。
用途固有の条件・保存・課金判定は各機能が担当し、すべてを同一画面へ押し込めない。
TDDは採用せず、実装後に変換・状態遷移・通知・保存の回帰テストを追加する。

## 方針の比較

| 方式 | 特徴 | 判断 |
| --- | --- | --- |
| 共通の選択画面・部品＋用途別の変換処理 | 検索と地図を一本化し、通知・震度条件は各機能に残せる | 採用案 |
| 全用途を一つの巨大な画面へ統合 | 入口は減るが、通知登録や複数選択などの分岐が集中する | 採用しない |
| 既存画面の見た目のみ統一 | 変更は小さいが、検索・地図・状態管理の重複が残る | 採用しない |

## 共通のユーザー体験

- 上部に地域種別、検索欄、「一覧／地図」切替を配置する。
- 種別は用途に応じて表示し、利用できない対象は候補に出さない。
- 一覧は名称検索と階層移動に対応する。名称・ふりがなを正規化して検索し、同名地域には親地域を添える。
- 地図のタップで範囲を強調し、下部の確認欄に種別・名称・決定ボタンを表示する。
- 一覧と地図で選択状態を共有する。表示切替では確定せず、明示的な決定で呼び出し元へ返す。
- すべての地域種別で単一／複数選択を呼び出し元から切り替えられる。同じ状態遷移と選択部品を使い、複数選択では選択済み一覧から解除できる。
- 既存の通知登録・ホーム・観測地域・ウィジェットは単一選択で接続する。震央地名フィルターは複数選択を使う。既存APIを複数の行政区域のOR検索へ拡張することは今回含めない。
- 既存選択を初期表示する。キャンセルは保存値を変更しない。解除は明示的な操作として区別する。
- 読込中・失敗・検索結果なし・地図で該当なしを区別し、再試行と戻る操作を提供する。

## 用途ごとの選択対象

| 用途 | 対象 | 固有の振る舞い |
| --- | --- | --- |
| 通知設定 | EEW細分化地域全域／配下の市区町村 | 地域を追加。既存の枠数・Pro判定・APIエラー処理を維持 |
| ホーム指定地域 | 都道府県／地震情報の細分化地域／市区町村 | 単一地域を保存。既存の指定解除とスコープを維持 |
| 地震履歴の観測地域 | 都道府県／地震情報の細分化地域／市区町村 | 選択地域の観測震度条件を併用 |
| 地震履歴の震央地名 | 震央地名 | 複数コードのいずれかに該当する地震を表示 |
| 地域名による地震検索 | 都道府県／地震情報の細分化地域／市区町村／震央地名 | 選択を対応する履歴条件へ変換。既存検索URLと初期検索語を維持 |
| ウィジェット設定 | 都道府県／市区町村 | 既存の保存形式・ネイティブ契約・Pro判定を維持 |

観測地域の条件と震央地名の条件は独立したフィルターとして併用する。
例えば「東京都で震度3以上を観測」かつ「震央地名が千葉県北西部」の検索を可能にする。
震央地名を変更・解除しても、地域・震度・期間・並び順など他の条件は保持する。
震央地名だけの検索に「選択地域の観測震度」という表現を使わない。

市区町村別最大震度マップは閲覧用の地図として維持する。
iOSショートカットのAppEntity選択はOS標準UIを維持する。
既存の観測点条件・保存値・ディープリンクは壊さず、今回の新規選択対象へ観測点を追加しない。
デバッグ用電文編集、緯度経度の矩形選択、全国／現在地の切替は本共通化の対象外とする。

## データと実装の境界

共通選択機能を `app/lib/feature/region_selection/` に配置する。
モデル・カタログRepository・検索ロジック・選択状態・画面・地図処理を分け、既存の類似型は移設または再利用する。
公開する選択結果は用途非依存の種別・コード・表示名と必要な親情報を持つ。
地域種別には都道府県、地震情報の細分化地域、EEW細分化地域、市区町村、震央地名を区別して持つ。
表示名が同じでも種別とコードの組で識別し、EEWと地震情報の細分化地域を相互代用しない。
地域選択そのものはAPI登録や設定保存を行わず、呼び出し元のActionが既存形式へ変換する。

通知の市区町村→EEW地域の結合は `NotificationRegionCatalogBuilder` の契約を再利用する。
結合不能な市区町村を近隣地域やコードの先頭一致で補わない。
複数の親候補がある市区町村は、通知用の地域階層から親を確定する。
都道府県→市区町村など他用途の階層とは区別する。

Riverpodの生成Provider、Hooks、保存時のMutation、Repository経由の外部アクセスを用いる。
Provider専用ファイルへモデルや検索ロジックを同居させない。
既存の `RegionIntensityResult` のようなUI側の型へのデータ層からの依存を解消する。
画面の呼び出し口はgo_router_builderで定義し、既存の検索URLは共通画面へ接続する。

## 地図とAsset Pack

2026-09-21に公開Asset Pack v0.1.0を取得し、既存検証ツールで署名・アーカイブを検証した。
`map/all.pmtiles` は `areaEpicenter` レイヤーを持ち、地物の `id` 属性は数値である。
実際のz0タイルには331地物、330種類のIDがあり、全IDが同梱 `area_epicenter` コード表へ対応した。
震央地名の名称はPMTilesに含まれないため、コード表と結合する。
コード表343項目のうち、広域名・遠地などに加え「岩手県沿岸南部」(211)もz0で見つからなかった。
全ズームでの欠落は未確認。z0の存在だけで選択候補を制限しない。

行政区域の判定は既存の常駐JMA workerを再利用し、描画・選択確認・非同期処理を共通化する。
震央地名は現在のJMA workerに対応種別がないため、Asset PackのPMTilesレイヤーから判定する。
MapLibreの `featuresAtPoint` を震央地名専用レイヤーへ限定して使い、`properties.id` をコード表で検証する。
描画されていないタイル、未知コード、該当地物なしは未選択とし、近隣の震央地名を推測しない。
同じIDの重複地物は一候補にまとめ、異なるIDが重なる場合は候補を提示して選ばせる。
検索ではコード表の全候補を扱い、範囲を描画できない候補も名称で選べる。
一覧から地図へ切り替えて範囲が得られない場合は選択値を保持し、地図確認ができない旨を表示する。

PMTilesの解決は `AssetPackRepository` を経由する。独立したダウンロード経路やURLの直書きを追加しない。
古いpackに震央地名レイヤーがない場合も一覧検索は維持し、地図選択にはAsset Pack更新の案内を出す。
検索結果と地図判定は同じ有効packに基づき、pack更新時に古いカタログ・地物判定を破棄する。
レイヤー操作は `MapOperationQueueScope` で直列化し、最新操作の世代とdisposeを確認する。
連続タップ、種別変更、画面終了後に古い非同期結果が選択を上書きしないようにする。
地図表示の色・境界・選択カードを統一する。MapLibreから別レンダラへの移行は含めない。

## 既存実装の整理

以下の選択実装は共通画面へ移行し、移行完了後に参照のなくなったコードを削除する。

- `core/component/selector/prefecture_selector.dart` と `city_selector.dart`
- `HomeDesignatedRegionPickerPage` の選択UIと `RegionPickerMapPage`
- `RegionIntensityFilterChip` 内の `_RegionIntensityPickerPage` の地域選択処理
- ウィジェット設定内の `_WidgetRegionPickerPage`
- 通知の `RegionPickerPage`、`CityPickerPage`、`NotificationRegionMapPickerPage` の重複UI
- `EarthquakeHistorySearchPage` の独立した検索UI・重複検索処理

呼び出し元の設定項目・フィルターチップ・通知登録Action・震度範囲部品は役割に応じて維持する。
通知固有のカタログ結合とコード変換を、見た目が似ているという理由だけで削除しない。
