# 地震活動可視化機能(公開版)+ Hi-net一元化震源ビューア(デバッグ) 設計

- 日付: 2026-07-03
- ステータス: 設計承認済み
- 関連Issue: [eqmonitor-backend#813](https://github.com/YumNumm/eqmonitor-backend/issues/813)(Hi-net backend取り込み・将来フェーズ)、[eqmonitor-backend#814](https://github.com/YumNumm/eqmonitor-backend/issues/814)(気象庁一元化カタログ取り込み・将来フェーズ)

## 背景

験震時報 第83巻4号「最新の地震活動推移を監視するための統合的なツールの開発」(気象庁「地震活動推移監視画面」の報告)を参考に、EQMonitor に地震活動の推移を可視化する機能を追加する。具体的には、震央分布図(色分け切替)、矩形選択による M-T 図・回数積算図・日別ヒストグラム・深さ断面図を実装する。

データソースについての調査結果と判断:

- **Hi-net の気象庁一元化処理 震源リスト**(`hinetwww11.bosai.go.jp/auth/JMA/jmalist.php`)は、NIED により**震源情報の二次配布が明示的に禁止**されている。一般公開アプリでの表示は二次配布に該当するリスクが高いため、**開発者本人のみが使うデバッグ画面に閉じる**。
- **公開版**は既存 DB(気象庁震度データベース + 気象庁防災情報XML、有感地震のみ・年間約2,000〜8,000件)を使用する。
- 気象庁が直接公開する一元化震源カタログ(地震月報カタログ編等、政府標準利用規約準拠で利用可)の取り込みは将来フェーズ(#814)。

## 全体アーキテクチャ

公開版とデバッグ版が**共通の可視化基盤**を共有する。可視化層は「震源イベントのリスト」だけに依存し、データの出所を知らない。

```
[公開版]
backend: 毎時CronJob ──生成──> 静的GeoJSON(直近1/3/12ヶ月の3ファイル) ──> 静的配信
manifest API ──> 震源レイヤーのソース記述 {type, span, url, generated_at, count}
app: manifest取得 → GeoJSON取得 → アプリ固有Freezedモデル → 可視化

[デバッグ版]
app(デバッグ画面): Hi-netフォーム認証(ID/PWは実行時入力) → jmalist.php からテキスト取得
             → パーサで同じFreezedモデルに変換 → 同じ可視化ウィジェットを再利用
```

共通イベントモデルのフィールド: `eventId`(Hi-net由来は合成ID)、`originTime`、`magnitude`、`depth`、`latitude`、`longitude`、`maxIntensity`(Hi-net由来はnull)。

### 配信方式の決定(案C: 静的GeoJSON + 抽象化)

- データ量: 有感地震のみのため直近12ヶ月でも gzip 後数百KB。静的GeoJSONで十分であり、クライアントが全イベントを保持できるため**矩形選択後の分析はすべてクライアント側計算で完結**する(追加APIなし)。
- manifest のソース記述に `type` フィールド(当面 `geojson` のみ)を持たせ、将来 Martin(ベクタタイル)導入時(#814)に `vector-tile` を追加してアプリ側の分岐だけで差し替えられるようにする。
- Martin を今回導入しない理由: ベクタタイルは低ズームで点が間引かれるため、M-T図等の分析には結局「矩形内の全イベント属性」を返す別経路が必要になり二重構造になる。現在のデータ量ではタイルサーバの運用コストに見合わない。

## Backend(公開版)

- **GeoJSON生成ジョブ**: `service/` 配下に新設。毎時のK8s CronJobで `earthquake` テーブルから以下の条件で取得し、1/3/12ヶ月の3つの GeoJSON FeatureCollection を生成する。
  - `originTime` が対象期間内
  - `latitude` / `longitude` が非NULL
  - `status = 'NORMAL'`
  - Feature properties: `event_id`, `origin_time`, `magnitude`, `depth`, `max_intensity` のみ(各地の震度観測点データは含めない)
- 生成物は既存の静的アセット配信の仕組み(manifest APIが参照する配信先)に載せる。具体的な配信先(オブジェクトストレージ/CDNの構成)は既存manifest配信の実装を確認して実装計画フェーズで確定する。
- **manifest API拡張**: 震源レイヤーの配列を追加。各要素は `{ type: "geojson", span: "P1M" | "P3M" | "P12M", url, generated_at, count }`。
- DBスキーマ変更なし。`origin_time` の既存btreeインデックスで毎時1回のクエリには十分。
- 取り込み・生成パターンは `packages/shindo-db-writer` 等の既存パターンに従う。

## アプリ(公開版) — 地震活動画面

新feature(`feature/seismicity` 相当)として実装。MapLibre地図 + 下部パネル(またはタブ)構成。

- **データ取得**: manifest → GeoJSON を取得し、アプリ固有のFreezedモデルに変換する(API型をUI層で使わない)。取得結果はローカルにキャッシュ。
- **震央分布図**: MapLibre circle レイヤーの data-driven styling。
  - 色分けモード切替: ①経過時間(古い=灰 → 直近=赤、験震時報方式)、②マグニチュード
  - 円サイズはマグニチュードに連動
  - 表示期間切替: 1 / 3 / 12ヶ月
- **矩形選択**: 地図上で矩形領域を指定すると、領域内のイベントをクライアント側でフィルタし以下を表示:
  - **M-T図**(時間 × マグニチュードの点プロット)
  - **回数積算図 + 日別ヒストグラム**(併記)
  - **深さ断面図**(緯度方向 / 経度方向の投影切替)
- チャート描画はアプリ既存のチャート実装パターンに従う(実装計画フェーズで確認して決定)。

## アプリ(デバッグ) — Hi-net一元化震源ビューア

- 既存のデバッグメニュー配下に新設。**一般ユーザーからは到達不可能**であること。
- **認証情報の扱い(厳守)**: NIEDアカウントのID/PWは画面で入力し `flutter_secure_storage` に保存する。**コード・設定ファイル・リポジトリには一切書かない。コミット禁止。**
- **取得**: Dio + Cookie管理でフォーム認証(`auth_un` / `auth_pw` をPOST → `_ssl_auth` Cookie取得)し、`jmalist.php` に `list_year` / `list_month` / `list_day` / `list_span` をPOST。
  - 1リクエスト最大7日分。期間指定に応じて直列リクエスト(ウェイト挟み、進捗表示付き)でサーバ負荷に配慮する。
  - データ利用可能期間: 2002/06/03〜直近。
- **パース**: `<pre>` 内のプレーンテキスト表(発生時刻、時刻誤差、緯度/経度と誤差、深さ、M1/M2、震央地名(英語)、品質コード)をパースし共通Freezedモデルへ変換。欠測フィールドや `FAR FIELD` 行はスキップしてスキップ件数を表示。
- **可視化**: 公開版と同じウィジェットを再利用。微小地震(M0台)を含むため、マグニチュード下限フィルタUIを付ける。

## エラー処理

- GeoJSON取得失敗: 前回取得分のローカルキャッシュにフォールバックし、`generated_at` による鮮度を表示。
- CronJob失敗: 既存の監視系(OTel)でアラート。前回生成ファイルが残るため配信自体は継続する。
- Hi-net認証失敗: 再入力プロンプト。パース不能行はスキップ + 件数表示。
