# 「このアプリについて」のテーマ対応と法的文書 WebView 化

## 目的

- 「このアプリについて」画面下部の本文をライト・ダーク両テーマで読めるようにする。
- 同画面が EQMonitor のデザインシステムを一貫して使用するようにする。
- 利用規約とプライバシーポリシーをローカル Markdown ではなくアプリ内 WebView で表示する。
- 設定画面とオンボーディングから同じ法的文書を表示する。

## 現状と原因

`AboutThisAppScreen` の下部本文は `BorderedContainer` 内の `MarkdownBody` で表示している。コンテナはデザインシステムの背景色と枠線色を使用しているが、Markdown はデザインシステム由来の文字色・書体を明示していない。この境界の不整合により、ダークテーマで本文色と背景色のコントラストが失われる。

利用規約とプライバシーポリシーは専用ページでアセットの Markdown を読み込んでいる。一方、オンボーディングには `InAppWebView` を使う画面があり、Web コンテンツをアプリ内表示する仕組みがすでに存在する。

## 採用設計

### 共通 WebView

オンボーディング専用の WebView Widget を共通コンポーネントへ移し、オンボーディングと法的文書の各ルートから再利用する。共通コンポーネントはタイトルと URL を必須入力とし、`InAppWebView` で URL を読み込む。

法的文書には次の URL を固定の正本として使用する。

- 利用規約: `https://eqmonitor.app/term_of_service`
- プライバシーポリシー: `https://eqmonitor.app/privacy_policy`

既存の `TermOfServiceRoute` と `PrivacyPolicyRoute` のパスは維持する。これにより設定画面・オンボーディングの呼び出し側とオンボーディング中のルーター許可条件を壊さない。両ルートの未使用パラメータである結果コールバックと `showAcceptButton` は削除する。ローカル Markdown を描画する専用ページも削除する。

### 読み込み・エラー状態

WebView の読み込み中はデザインシステム色を使うインジケーターを表示する。メインフレームの読み込みに失敗した場合は、例外文字列を直接表示せず、利用者向けの短いメッセージと再読み込み操作を表示する。サブリソースの失敗はページ全体のエラーへ昇格させない。

### 「このアプリについて」画面

画面内の余白、角丸、文字、アイコン、区切り線、Markdown の各スタイルを `context.designSystem` の spacing、shape、typography、colorTheme から構築する。

Markdown は少なくとも本文、見出し、リスト、リンク、コードの文字色と書体をデザインシステムに合わせる。本文背景には `surfaceContainer`、本文には `onSurface` または `onSurfaceVariant`、リンクには `primary` を使用し、ライト・ダーク両テーマでコントラストを保つ。

スクロール構造は `SingleChildScrollView` と `Column` から `ListView` へ変更する。テキスト領域に固定高さは設定せず、文字サイズ拡大時も内容をスクロールできるようにする。

## データフロー

1. 設定画面またはオンボーディングで法的文書リンクをタップする。
2. 既存の法的文書ルートが、タイトルと正本 URL を共通 WebView へ渡す。
3. WebView がページを読み込み、進捗またはエラー状態を画面内に反映する。
4. 「このアプリについて」の説明本文は従来どおりローカル Markdown アセットから読み込み、デザインシステムのスタイルで描画する。

## テスト方針

実装はテスト駆動で行う。

- ライト・ダークそれぞれで「このアプリについて」の Markdown 本文が対応テーマの文字色を使う Widget テストを追加する。
- 画面がデザインシステムの余白・背景・本文スタイルを使うことを、利用者に見える Widget の属性で検証する。
- 利用規約・プライバシーポリシーの各ルートが、指定されたタイトルと正本 URL の共通 WebView を構築するテストを追加する。
- 共通 WebView の読み込み中・メインフレームエラー・再読み込み操作は、WebView コントローラー境界を置き換え可能な範囲で Widget テストする。
- 対象テスト、静的解析、関連する既存テストを `mise exec --` 経由で実行する。

## 対象外

- Web サイト側の利用規約・プライバシーポリシー本文の変更
- 課金画面にある外部ブラウザ遷移の変更
- 「このアプリについて」以外の Markdown 表示の全体改修
- WebView のナビゲーション制限や独自ブラウザ機能の追加
