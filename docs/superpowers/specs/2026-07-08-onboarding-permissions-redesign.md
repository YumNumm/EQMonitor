# Onboarding Permissions Redesign

- Date: 2026-07-08
- Target: Flutter app (`app/`)
- Scope: Onboarding permission step and related onboarding navigation state

## Background

現在のオンボーディング権限ページは、下部の「次へ」ボタンで通知権限と位置情報権限をまとめて要求する。
ユーザーはどの権限が何に使われるかを理解しにくく、拒否・スキップ・許可済みの状態も画面上で追いづらい。

また、`OnboardingPage` は `InheritedWidget` と各ステップの `useEffect` で下部ボタン状態を差し込む構造になっている。
ステップが増えたり、権限のように複数の局所状態を持つ画面では、親子間の状態更新が読みづらくなる。

## Goals

- 通知権限、重大な通知、アプリ使用中の位置情報、バックグラウンド位置情報を分けて説明し、個別に許可・スキップできるようにする。
- 下部の「次へ」ボタンは初期無効にし、ユーザーが表示中の各権限項目を許可またはスキップした後だけ有効化する。
- オンボーディング全体のナビゲーション状態を整理し、各ステップが親へ `useEffect` で状態を注入する構造を減らす。
- 位置情報に関するQ&Aリンクはアプリ内WebViewで開く。正式ページができるまでは `https://example.com` を開く。

## Non-Goals

- Widget Test は今回追加しない。
- Web上のQ&A本文は作成しない。アプリ側は一時的に `https://example.com` を開く。
- 通知設定ステップのプリセット仕様は変更しない。
- 位置情報の精度やバックグラウンド取得のプラットフォーム制約そのものは変更しない。

## Overall Onboarding State Design

`OnboardingPage` はページ遷移と下部バーの制御に責務を寄せる。
現在ステップ、戻る/次へ、ボタンラベル、次へ有効状態、処理中状態は親側の明示的な状態として保持する。

各ステップは、次の情報を親に渡せる形にする。

- 下部ボタンのラベル
- 次へボタンを有効にできるか
- 処理中か
- 次へ時に実行する処理

既存の `_OnboardingScope` に `setStepNavigation` を渡し、各ステップが `useEffect` で親状態を更新する構造は見直す。
実装では、親から各ステップへコールバックを渡す、または小さな controller/model を導入して「ステップが現在のナビゲーション状態を宣言する」形に寄せる。

これにより、権限ページのような複数状態を持つステップでも、下部バーの状態更新を追いやすくする。

## Permissions Step Layout

権限ページは縦方向の `Column` を基本に、内容が画面に収まらない端末ではスクロールできる構造にする。
大きく2セクションに分ける。

1. 通知権限
2. 位置情報権限

各権限項目は、説明文、状態表示、アクションボタンを持つ小さなカードまたはセクションとして表現する。
状態は最低限 `notRequested`, `granted`, `skipped` を持つ。
権限要求が拒否された場合は `notRequested` のままに戻し、Snackbar で知らせる。
表示対象の各権限項目は、許可ボタンと小さめのスキップ操作を持つ。

## Notification Permission Section

### 1-1. 通知を許可

表示文言:

- 見出し: `通知を許可`
- 説明: `地震情報や緊急地震速報を通知でお知らせします。通知を送る条件や地域はこの後設定できます`

初期状態では `[スキップ] [許可する]` を表示する。
`スキップ` は小さめのボタンにする。

許可するボタンでは Firebase Messaging の通知権限を要求する。
`AuthorizationStatus.authorized` または `AuthorizationStatus.provisional` なら `granted` として扱い、表示を `[許可しました]` に変える。
権限が付与されなかった場合は Snackbar で知らせ、ボタン表示は `[許可する]` のままにする。

`スキップ` を押した場合、通常通知を `skipped` にし、重大な通知も自動的に `skipped` にする。

### 1-2. 重大な通知を許可

重大な通知は対応環境のみ表示する。
非対応環境ではセクション自体を表示しないため、次へ有効化条件にも含めない。

表示文言:

`現在地を警報地域とする緊急地震速報(警報)が発表されたときに、おやすみモードやマナーモードを無視して強制的に通知を配信します。`

通常通知が `granted` になった後に操作可能にする。
許可できた場合は `granted` とし、付与されなかった場合は Snackbar で知らせて `notRequested` のままにする。
スキップした場合は `skipped` として扱う。

## Location Permission Section

セクション冒頭に説明文とリンクを表示する。

説明:

`端末の位置情報を利用して、適した通知をお知らせします。`

リンク:

`EQMonitorにおける位置情報の扱い方`

リンクは `Text.rich` で実装し、アプリ内WebViewで `https://example.com` を開く。

### 2-1. アプリを開いている時の位置情報

表示文言:

- `緊急地震速報発表時に現在地の予想震度と到達までの時間を表示します。`
- `気象庁が現在地の予想震度と到達予想時刻を発表した場合に限ります。`
- `地震情報を開いた時に、現在地付近で観測した震度を表示します`

`詳しい情報` リンクも `Text.rich` で実装し、アプリ内WebViewで `https://example.com` を開く。

`許可する` ボタンで `Geolocator.requestPermission()` を呼ぶ。
`LocationPermission.whileInUse` または `LocationPermission.always` を許可として扱う。
許可された場合は `granted` とし、2-2 を操作可能にする。
付与されなかった場合は Snackbar で知らせ、2-1 は `notRequested` のままにする。

2-1 をスキップした場合、2-2 も自動的に `skipped` にする。

### 2-2. アプリを開いていない時の位置情報

2-1 が `granted` の場合だけ操作可能にする。
2-1 が未完了の場合は、2-1 の許可が必要であることを説明する無効表示にする。

表示文言:

- `現在地で緊急地震速報(警報)が発表された時に重大な通知でお知らせします`
- `注意!: 高速で移動している場合やネットワーク環境が悪い場合、低電力モードにしている場合、前の位置情報で通知が配信される場合があります。`
- `現在地で揺れを観測した地震情報が発表された場合のみ通知することができます。この後の通知設定で細かく設定できます`

`許可する` ボタンで、バックグラウンド利用に必要な権限要求を行う。
`LocationPermission.always` を許可として扱う。
付与されなかった場合は Snackbar で知らせ、2-2 は `notRequested` のままにする。
スキップした場合は `skipped` として扱う。

## Next Button Completion Rule

下部の「次へ」ボタンは初期無効。
次の条件を満たした場合だけ有効にする。

- 表示されている通知項目がすべて `granted` または `skipped`
- 表示されている重大な通知項目が `granted` または `skipped`
- 位置情報 2-1 が `granted` または `skipped`
- 位置情報 2-2 が `granted` または `skipped`

非対応環境で表示しない項目は条件に含めない。

## WebView Page

オンボーディング中でも開けるアプリ内WebViewページを追加する。
正式なQ&Aページができるまでは、位置情報の扱い方と詳しい情報のどちらも `https://example.com` を開く。

ルートは `go_router_builder` に合わせて追加し、オンボーディング未完了時のリダイレクト例外にも含める。
画面タイトルはリンク元に応じて変えられるようにする。

## Testing

Widget Test は追加しない。

権限ページの完了判定や項目状態の派生が複雑になる場合は、純粋な Dart の model/controller に切り出し、単体テストを追加する。
単体テストで確認する候補は次の通り。

- 初期状態では次へ不可
- 通知スキップで重大な通知もスキップになる
- 重大な通知非対応環境では完了条件に含まれない
- 2-1 スキップで 2-2 もスキップになる
- 2-1 許可後だけ 2-2 が操作可能になる
- 表示対象の全項目が `granted` または `skipped` になった時だけ次へ可能

## Implementation Notes

- `.g.dart` は直接編集しない。ルートや Riverpod 生成が必要な場合は `mise exec -- melos run generate` または対象パッケージの build_runner で再生成する。
- Flutter / Dart コマンドは `mise exec --` 経由で実行する。
- 権限要求のSDK呼び出しはUIに直書きしすぎず、状態判定ロジックはテスト可能な小さな型へ寄せる。
- Snackbar 文言は、権限が付与されなかったことと後から設定で変更できることを短く伝える。
