# テーマ設定の戻るナビゲーション修正

## 背景

設定画面から表示設定を開く導線は `push` で画面を履歴に積んでいるが、
表示設定からテーマ設定を開く導線は `go` で現在のルート構成を置き換えている。
テーマプリセットを変更するとアプリ全体の `ThemeData` が再構築され、
URL由来のルート構成が再評価された結果、テーマ設定画面の AppBar が
戻れる画面を認識できず、戻るボタンが消える。

## 方針

表示設定からテーマ設定へのユーザー操作は階層を深く進む操作であるため、
`ThemeSettingsRoute.go` を `ThemeSettingsRoute.push` に変更する。
表示設定画面を明示的な履歴として保持し、テーマ変更による再構築後も
Navigator の `canPop` が維持されるようにする。

AppBar に独自の戻るボタンは追加しない。標準の自動 leading を利用し、
実際のナビゲーション履歴と表示を一致させる。

## 対象範囲

- 表示設定からテーマ設定への遷移方法
- テーマプリセット変更後の戻る操作に対する Widget 回帰テスト

テーマエディターへの遷移や設定配下全体のルート再設計は対象外とする。

## 期待する挙動

1. 設定画面から表示設定を開く。
2. 表示設定からテーマ設定を開く。
3. ライト用テーマのプリセットを変更する。
4. テーマ設定の AppBar に戻るボタンが表示されたままになる。
5. 戻るボタンを押すと表示設定へ戻る。

## テスト

実際の `GoRouter` とテーマ状態を使う Widget テストを追加する。
修正前はプリセット変更後の戻るボタンまたは戻り先の検証で失敗し、
`push` への変更後に成功することを確認する。

既存のテーマプリセット保存テストも実行し、保存動作に回帰がないことを確認する。
