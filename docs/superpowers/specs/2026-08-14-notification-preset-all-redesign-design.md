# 通知プリセット再設計（「すべて」の条件・全件置換・カスタム復元）設計

## 概要

通知プリセットの「すべて」が実際には全国震度3以上に留まっていた問題を解消し、プリセット適用を「既存スロットを全削除してからプリセットの条件を投入する」方式へ変更する。あわせてカスタム設定をローカルへ退避し、カスタムへ戻したときに復元できるようにする。

## 背景

現状の問題は次のとおり。

- 「すべて」の全国スロットが震度3以上で、名称と条件が一致しない
- プリセット適用が現在地スロットの上書きのみで、カスタムで追加した地域スロットや全国スロットがサーバに残り続ける。表示上のプリセットと実際の通知条件が乖離する
- プリセットが EEW・地震のグローバル有効フラグを ON に戻さないため、過去に OFF にした端末では「すべて」を選んでも通知が届かない
- 「すべて」が南海トラフ通知を含まない
- 現在地スロットの最小震度がドロップダウンで自由に変更できるため、プリセットの想定と異なる値になりうる

## プリセット定義

| プリセット | 現在地 | 全国 | 地域 | 一般通知 |
|---|---|---|---|---|
| 推奨設定 | EEW予報 震度4以上 / 地震 震度1以上 | なし | なし | 通知マスターON、EEW・地震グローバルON、EEW警報ON |
| すべて | 同上 | EEW予報 すべて / 地震 すべて | なし | 推奨設定に加え南海トラフ（臨時情報・関連解説）ON |
| カスタム | スナップショットがあれば復元。無ければ推奨設定と同じ現在地スロットのみ | スナップショット依存 | スナップショット依存 | スナップショット依存 |
| 通知しない | なし（全スロット削除） | なし | なし | 通知マスターOFF |

「すべて」に含めないものは、訓練通知（デバッグ用途）と津波通知（未実装）、EEW警報の全国対象（Pro限定機能のため既存値を維持）。

## 震度「すべて」の意味論

最小震度 `0` を「すべて」として扱う。バックエンドの PostgreSQL enum `jma_intensity` は `'0'` が最小値で、マッチ条件が `min_intensity <= イベント震度` のため、`'0'` は常に真になる。API・DB・配信ロジックの変更は不要。

UI 上のラベルのみ「震度0」から「すべて」へ変更する。

### 既知の制約（本設計のスコープ外）

EEW の予想最大震度が不明で、かつ地域情報も無い電文は、`notification-resolver` のマッチング入口（`handlers/earthquake/device-matcher.ts`）で対象デバイスなしとして打ち切られる。全国スロットを「すべて」にしてもこの種の電文は配信されない。本変更で新たに発生する問題ではないため、`docs/todo/` に課題として記録し別途対応する。

## 震度選択UI

| 対象 | 選択肢 |
|---|---|
| 現在地 EEW予報 | 震度4のみ（固定表示、ドロップダウンなし） |
| 現在地 地震情報 | 震度1のみ（固定表示、ドロップダウンなし） |
| 全国 EEW予報 | すべて、震度1〜7 |
| 全国 地震情報 | すべて、震度1〜7 |
| 地域 | 従来どおり（すべて、震度1〜7） |

「すべて」を先頭（最小）に置き、以降は震度の昇順に並べる。

現在地の固定値は UI だけでなく `NotificationSlotRepository` でも強制し、UI を経由しない経路でも崩れないようにする。

## サーバ側: スロット全件置換API

`PUT /v2/device/me/settings/slots` を新設する。

- リクエストはスロット配列。空配列は全削除を意味する
- `SlotDatasource.replaceSlots` が単一トランザクションで `DELETE` 全件 → `INSERT` を実行する
- 失敗時はロールバックされ、旧スロットが残る。「全部消えたまま失敗する」状態が起きない
- 地域スロット数のプラン上限を検証し、超過時は 402 を返す
- `current_location` / `nationwide` は各1件までを検証し、超過時は 400 を返す
- レスポンスは置換後の全スロット一覧

既存の揺れ検知設定 `replaceShakeDetectionSettings` と同じ全件置換パターンに揃える。新たな service 層は設けない。

## クライアント側: プリセット適用Workflow

`packages/workflows` の `WorkflowRunner` を使い、再開可能な処理として実装する。ステップは次の順序。

1. `saveCustomSnapshot` — カスタムから離脱する場合のみ、現在のサーバ状態をスナップショットとして保存
2. `replaceSlots` — プリセットのスロット構成へ全件置換
3. `restoreCustomSettings` — カスタムを選択した場合のみ、スナップショットの一般通知・グローバル設定を書き戻す
4. `updateGeneralSettings` — 通知マスター、南海トラフ等の一般通知設定を更新
5. `updateGlobalSettings` — EEW・地震のグローバル設定（有効化）を更新
6. `selectPreset` — プリセット種別を SharedPreferences へ保存

各ステップは冪等で、途中で失敗しても次回同じ `instanceId` で再開すると未完了ステップから続行する。完了後に Workflow インスタンスを破棄する。

## カスタム設定のスナップショット

保存対象は次のとおり。

- 全スロット（現在地・全国・地域）の種別、地域コード、市区町村コード、表示順、EEW・地震の有効状態と最小震度、震度別オーバーライド
- EEW警報の対象と全国割り込みレベル
- EEWグローバル設定（有効、通知音、割り込みレベル、Live Activity、まとめ表示、警報有効）
- 地震グローバル設定（有効、通知音、割り込みレベル、推計震度分布図、まとめ表示）
- 一般通知設定（通知マスター、南海トラフ2種、後発地震注意情報、お知らせ）

保存先は SharedPreferences。キーは `SharedPreferencesKey` に `notificationCustomSnapshot` を追加する。値はスキーマバージョン付きの JSON。

Freezed モデル群に `toJson` が無いため、スナップショット専用モデルを新設し、JSON 変換とアプリモデルとの相互変換を持たせる。復元時に Pro 制約（地域数上限、オーバーライド利用可否）を超える内容は、超過分を落として復元する。

## エラーハンドリング

- Workflow のステップ失敗は Mutation のエラーとして UI に伝播し、既存の `showErrorDialog` で表示する。プリセット種別の保存（最終ステップ）に到達していないため、UI の選択状態は変わらない
- 402（プラン上限超過）は「Proプランが必要です」という趣旨のメッセージへ変換する
- スナップショットの JSON パース失敗は、スナップショット無しとして扱い、カスタムは現在地スロットのみで初期化する

## 切替時の確認ダイアログ

カスタムから他プリセットへ切り替えるときに確認ダイアログを表示する。文言はカスタム設定が解除されること、および再度カスタムを選べば元に戻せることを伝える。キャンセル時は選択を変更しない。

## テスト

| 対象 | 内容 |
|---|---|
| `SlotDatasource.replaceSlots` | 全削除→投入、空配列、CHECK 制約違反時のロールバック |
| `PUT /v2/device/me/settings/slots` | 正常、空配列、地域上限超過（402）、singleton 重複（400）、バリデーション（400） |
| 震度選択肢 | 全国・地域の選択肢の内容と順序、現在地の固定値 |
| 震度ラベル | 震度0 が「すべて」と表示される |
| `NotificationSlotRepository` | 現在地の最小震度が 4 / 1 に強制される |
| プリセット適用Workflow | 各プリセットの置換内容、南海トラフ ON、グローバル有効化、ステップ再開 |
| スナップショット | 保存・復元の往復、スキーマ不一致時のフォールバック、Pro 制約超過時の切り詰め |
| 確認ダイアログ | カスタムからの切替で表示、キャンセル時に選択が変わらない |

## スコープ外

- 津波通知（未実装）
- 揺れ検知設定のプリセット連動
- EEW警報の全国対象をプリセットで変更すること
- EEW の予想最大震度が不明な電文の配信（`docs/todo/` に記録）
