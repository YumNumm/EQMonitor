# 通知配信ログ詳細の一般ユーザー向け表示設計

## 背景

通知配信ログの項目をタップすると詳細 Sheet は開くが、見出し以外が表示されない。
現在の実装では、過去の変更により詳細項目の一覧とスクロール領域が削除され、
処理を持たないコピーボタンだけが残っている。また、ログが空のときに端末 ID が
表示されており、一般ユーザーには不要な内部情報を露出している。

## 目的

- 一般ユーザーが通知の配信内容と結果を確認できる詳細 Sheet を復旧する。
- 一般ユーザーの判断や問い合わせに役立たない内部情報を表示しない。
- ログが空の状態から端末 ID を削除する。

## 表示仕様

詳細 Sheet には次の項目を表示する。

1. 配信日時
   - API の ISO 8601 文字列を端末のローカル時刻へ変換する。
   - 日本語 UI に合わせ、年・月・日・時・分・秒を判別できる形式で表示する。
   - 解釈できない日時は情報を失わないよう受信した文字列を表示する。
2. 配信結果
   - `ok` は「成功」、`ng` は「失敗」と表示する。
3. タイトル
   - 値がある場合だけ表示する。
4. 本文
   - 値がある場合だけ表示する。
5. エラー内容
   - 配信結果が失敗で、エラーメッセージが空でない場合だけ表示する。

`deviceId`、`streamId`、`eventId`、配信フレームワーク、通知チャネル、
各種 priority などの配信基盤固有情報は表示しない。

コピーボタンは、Sheet に表示している一般ユーザー向け項目だけをラベル付きで
クリップボードへコピーする。コピー完了時は SnackBar で通知する。

ログが空の場合は「配信ログはまだありません」の案内だけを表示し、端末 ID は
表示しない。プルダウン更新は維持する。

## 設計

表示項目の選択、日時整形、結果ラベル、コピー文字列の生成は、Widget から分離した
詳細表示用モデルのビルダーに集約する。ビルダーは `PushNotificationLogEntry` を受け、
ラベルと値からなる表示行、およびコピー文字列を返す。Riverpod で DI し、Widget は
生成済みの表示行を描画することだけを担当する。

Sheet 本体は `DraggableScrollableSheet` と `ListView` を使い、文字拡大や長文でも
スクロール可能にする。固定高さを設けず、空のタイトル・本文・エラー項目は描画しない。

## エラー処理

- 日時の解析失敗によって詳細 Sheet 全体を表示不能にしない。
- 失敗時の `errorMessage` はユーザーが配信失敗を確認する補助情報として表示する。
- `errorCode` は内部情報のため表示・コピー対象にしない。

## テスト

- 表示用モデルの単体テスト
  - ローカル日時と成功・失敗ラベルを生成する。
  - 成功時はエラー項目を含めない。
  - 失敗時は空でないエラーメッセージだけを含める。
  - 内部識別子・配信基盤固有値を含めない。

ユーザー承認により TDD と Widget Test は行わない。表示ロジックの単体テストと
Flutter Analyze で変更を検証する。

## 対象外

- API レスポンスや保存形式の変更
- 通知配信履歴の取得・ページネーション方式の変更
- 通知設定や実際の配信処理の変更
