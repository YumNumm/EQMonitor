# EEW履歴リプレイの時刻整合修正計画

**目的:** 報・P/S波・到達表示を実際の発表時刻にそろえ、再生操作の不整合を修正する。

**設計:** `EewSimulationState` を再生時刻の正本とする。報間隔の上下限を廃止し、
停止と完了時も同じ時刻を参照する。再生状態は詳細画面ごとに保持する。

**技術:** Dart、Riverpod、Flutter Hooks、MapLibre。

**仕様:** ユーザーの修正・追加調査依頼と `docs/knowledge/eew_realtime.md`。

## 制約と確認範囲

- `origin/develop` の専用worktreeで実装し、`develop` 向けPRを作成する。
- 既存テストと静的解析で検証する。テスト追加・TDDは行わない。
- 地震の欠測値を補わず、発表済みの到達情報を優先する。
- 実機の描画と停止・復帰操作は未検証として既存TODOに残す。

## 1. 再生時間と操作

- [ ] `eew_simulation_notifier.dart` の報間隔を先頭報との実際の時刻差にする。
- [ ] 同時刻の報を報番号順にし、共通の仮想時刻と最終報での固定位置を定義する。
- [ ] 詳細画面の再生状態を分離し、最終報の選択と完了後の再生を修正する。
- [ ] 地図とカードから同じ仮想時刻を参照する。

## 2. 到達表示と波面

- [ ] 到達前の端数秒を切り上げ、時刻未取得を到達済みとして表示しない。
- [ ] 走時表の時刻に完全一致する際のゼロ除算を除去する。
- [ ] 停止中に走時表が読み込まれた場合も波面を更新する。
- [ ] 再生を巻き戻した場合に後の報の推定結果を持ち越さない。

## 3. 検証とPR

- [ ] 既存の再生、カード、走時、履歴、再生権限のテストを実行する。
- [ ] 生成コードを再生成し、変更範囲・削除差分を確認する。
- [ ] Dart解析、format、textlint、hk、差分確認を完了する。
- [ ] 独立レビューを依頼し、必要な修正を反映する。
- [ ] 論理単位でcommit・pushし、PRと実際のCI状態を報告する。
