# App Intents の実機検証と残る連携課題

Issue: https://github.com/YumNumm/EQMonitor/issues/1794

## 2026-09-10 に対応した項目

- 音声応答、全体最大震度と地域震度、訓練・試験・発生/検知時刻の区別。
- 初回戻り値とカードを同一スナップショット化。明示更新はカードのみ更新と表示。
- 保存地域名と「位置の取得時刻不明・現在地とは限らない」を表示・読み上げ。保存コードが変わった古いカードの更新はエラー。
- 主Intent・カード・更新で地域/件数検証とPro判定を共通化。不正IDの全国フォールバックを廃止。
- Entityの詳細APIによるID復元、訓練/試験、日時/数値/震度分類。地域検索時だけ地域震度を返す。
- SwiftスキーマのIntensityPartialに加え、Earthquake/Intensityも必要フィールドを元スキーマから限定再生成。
- 通信・デコード失敗の短い日本語案内、拡張表示名と生成NLUのEQMonitorへの統一。
- Intent実行・取得回数・カード再描画・明示更新・Entity復元・欠損/エラーの自動テスト追加。

## 残る確認・改善

1. 署名した実機で「EQMonitorで最新の地震を確認」の解決、Snippetの表示・明示更新、Pro失効、保存地域変更、オフライン時の音声を確認する。
   拡張のメタデータ生成だけで本体への登録成功とは判断しない。
2. 既存Widget/SnippetのOpenURLIntentはカスタムスキーム。Appleの契約に合わせUniversal Linkへ移行するには、まずdeeplink.eqmonitor.appのDNS/AASAと実機導線を復旧・検証する。
   2026-09-10の接続確認では名前解決に失敗した。
3. 将来「現在地」として扱う場合は、Flutterの全保存経路で位置の観測日時を共有し、位置取得失敗時の保持・期限切れ・権限取消を含む契約とテストを追加する。現状は常に保存地域として扱う。
4. Flutterの履歴時刻表示がoriginTimePrecisionを尊重するよう別途修正する。今回のEntity・音声応答は精度を尊重する。
5. Swiftの元スキーマにない旧Live Activity操作5件を整理し、限定生成に依存しない全生成へ戻す。
6. Siri検索連携は地域名候補の選択まで。自然文の日付・震度・複合条件は未対応。
