# 修正依頼時のテスト方針

## 原則

- 修正依頼では、回帰テストや Widget Test を含む自動テストの新規作成は不要。ユーザーがテスト追加を明示的に依頼した場合のみ行う。
- TDD（テスト駆動開発）も、ユーザーが明示的に依頼した場合のみ行う。テスト先行や RED → GREEN の証跡を修正の前提にしない。
- 緊急情報の判定、データ変換、状態遷移、通知条件、永続化、障害修正にも同じ方針を適用する。変更リスクだけを理由にテスト追加を必須にしない。
- 変更に関連する既存テストと静的解析で確認する。既存テストの実行や CI の確認は、テストの新規作成とは別に扱う。
- テストを新規作成しない理由の説明は不要。
- 過去の計画にある TDD 手順や回帰テスト追加の要件は当時の作業記録として扱い、新しい修正依頼へ引き継がない。現在のユーザー指示と本方針で検証方法を決める。

## 既存テストと静的解析による確認

アプリコードの変更では、変更機能の既存テストがあれば実行し、変更対象の静的解析を行う。対応する既存テストがない場合も、新規作成は不要。作業結果には実行した確認と結果、未実施の確認があればその内容を記載する。

```bash
cd app
mise exec -- flutter test test/feature/<feature> --dart-define=CI=true
mise exec -- flutter analyze lib/feature/<feature>
```

ドキュメントのみの変更ではアプリのテスト追加や実行を必須とせず、リンク先の存在、記述と現行設定の整合、差分、適用対象の Markdown lint を確認する。
