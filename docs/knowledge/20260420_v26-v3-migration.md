# v2.6 → v3 デバイス移行 知見メモ (2026-04-20)

## 概要

v2.6 系（Supabase バックエンド）から v3（現バックエンド）への移行は、
旧デバイス ID を SharedPreferences から読み、サーバー側の `POST /v2/device/{id}/migrate` で設定を引き継ぐ。

## ストレージキー

| 用途 | キー | ストレージ |
|------|------|-----------|
| v2.6 旧デバイス ID | `device_id` (`kLegacyDeviceIdKey`) | SharedPreferences |
| ワークフローステップ結果 | `_wf:<instanceId>:<stepName>` | SharedPreferences |
| ワークフローマニフェスト | `_wf:__m__:<instanceId>` | SharedPreferences |
| 移行完了フラグ (step name) | `markLocalComplete` | ワークフロー永続化 |

`kLegacyDeviceIdKey` の実値は `app/lib/feature/migration/data/repository/migration_repository.dart` で定義。v2.6 アプリの実際のキーに合わせて調整が必要になる場合がある。

## 移行シーケンス

```
old_device_key 読み取り
       │
  値あり ──→ durable workflow (kV3MigrationInstanceId)
  値なし ──→ noLegacyId → (TODO) オンボーディング
               │
               ├─ step: ensureDeviceAbsent
               │    GET /v2/device/{id}
               │    200 → alreadyRegistered=true
               │    404 → alreadyRegistered=false
               │
               ├─ step: registerDevice  (alreadyRegistered=false のみ)
               │    PUT /v2/device/{id}
               │
               ├─ step: migrateLegacySettings
               │    POST /v2/device/{id}/migrate  {old_device_id: ...}
               │    409 → 冪等完了として正常扱い
               │
               └─ step: markLocalComplete
                    true を永続化 → 以後 isMigrationComplete() = true
```

## ヘッダー付与ルール

`DeviceIdInterceptor` が `/v2/device/` 配下のリクエストに `X-eqmonitor-device-id` を付与する。
ただし `PUT /v2/device/{deviceId}`（デバイス登録）は App Check 認証のみを使うため付与しない。

## エラー分岐

| HTTP | 箇所 | 処理 |
|------|------|------|
| 404 | GET /device | 未登録 → PUT へ進む |
| 409 | POST /migrate | 既に移行済み → 冪等完了 |
| その他 | どこでも | `V3MigrationState.failed` を返す (Provider が吸収) |

## 耐久性

`packages/workflows` の `WorkflowRunner` を利用。同一 `instanceId` で再起動後に呼ぶと最後に完了したステップの次から再開する。
