# realtime_seismic_intensity

3成分の加速度波形（gal）から、リアルタイム震度を計算する純 Dart パッケージ。記録全体を一度に計算する場合は、計算周期を 0.1 秒などに短くできる。
K-NET・KiK-net の強震記録を再生するときに、強震モニタと同じ尺度の値を観測点ごとに求めるために使う。

計算は [ingen084/seismometer](https://github.com/ingen084/seismometer)（MIT License）の `IntensityFilter`・`IntensityProcessor` を移植したもの。

## 特許について

震度計算用の6段のフィルタ（`JmaIntensityFilterDesign` の A11〜A14）は、
[特許第5946067号](https://www.plidb.inpit.go.jp/pldb/html/HTML.L/2016/001/L2016001200.html)
「計測震度概算装置及びそれを用いた計測震度概算システム」の文書に示された式で実装している。

| 項目 | 内容 |
| --- | --- |
| 出願番号 | 特願2013-107798（出願日 2013-05-22） |
| 特許権者 | 国立研究開発法人防災科学技術研究所 |
| 実施許諾 | 可（開放特許情報データベースの記載） |
| 存続期間 | 出願日から20年で、2033-05-22 まで存続する可能性がある。年金の納付状況は未確認 |

- この処理を使って利益を得る場合、防災科学技術研究所とのライセンス契約が必要である（移植元の README の記載）。
- EQMonitor は有料プランと広告を含むため、この処理を組み込んだアプリの配布は「業として」の実施に当たる可能性がある。
  リリースへ含める前に、防災科学技術研究所とのライセンス契約の要否を確認すること。
- 0.05 Hz のハイパスフィルタは、一般的な2次バターワースフィルタで、特許の対象外である（移植元の記載）。
- このパッケージは気象庁の検定を受けた震度計ではない。算出値は計測震度に相当する値であり、気象庁が発表する震度ではない。

## 使い方

記録全体を一度に計算する場合は `RealtimeIntensitySeriesCalculator` を使う。

```dart
final series = const RealtimeIntensitySeriesCalculator().calculate(
  startTime: firstSampleTime,
  samplingRate: 100,
  ns: ns,
  ew: ew,
  ud: ud,
  stepsPerSecond: 10,
);
final intensity = series.valueAt(replayTime);
```

- 計算周期は `stepsPerSecond`（既定値 1）で決まり、サンプリング周波数を割り切れる値に限る。100 Hz で 10 なら 0.1 秒（10 サンプル）ごと。
- `values[i]` は、先頭から `i` 周期後〜`i + 1` 周期後の波形までを使った値で、`i + 1` 周期後に確定する。`valueAt` はその時点で確定済みの最新の値を返す。
- 窓のサンプル数が `floor(0.3 × サンプリング周波数)` に満たない先頭の周期・記録の終端以降・加速度が 0 の周期は `null`。
- 各成分から記録全長の平均値（オフセット）を差し引いてから計算する。防災科研が公開する最大加速度と同じ扱いで、再生専用の非因果的な処理である。
- 末尾の1周期に満たないサンプルは使わない。

逐次計算する場合は `RealtimeIntensityCalculator.addSecond` に1秒分（`samplingRate` 個）ずつ渡す。オフセットは呼び出し側で除く。

## 計算方法

1. 各成分に 0.05 Hz の2次バターワースハイパスフィルタを掛ける。係数はサンプリング周波数から双一次変換（プリワープあり）で求める。
2. 特許の式による6段の2次 IIR フィルタを掛け、1.262 倍する。
3. 3成分を合成した絶対値を求める。
4. 直近60秒の合成値を大きい順に並べ、`floor(0.3 × サンプリング周波数)` 番目の値 `a` を求める。100 Hz では30番目。
5. `2 log10(a) + 0.94` を小数第3位で四捨五入し、小数第2位以下を切り捨てる。負の値は小さい側の 0.1 刻みになる。

- 逐次計算（`RealtimeIntensityCalculator`）は、各秒の上位 `floor(0.3 × サンプリング周波数)` 個だけを保持し、窓内の各秒の先頭を比べて取り出す。
- 一括計算（`RealtimeIntensitySeriesCalculator`）は、記録全体の合成値に大小の順位を付け、窓に入っている順位を Fenwick 木で数えて、各周期の `a` を O(log n) で引く。
  順位付けは、0 以上の倍精度浮動小数点数のビット列を整数とみなした基数ソートで行う。`Int64List.sort` では 30,000 サンプルで約 35 ms かかり、基数ソートでは約 1.8 ms だった。差は汎用の比較で要素がボックス化されるためと考えられる。
- 1秒刻みの一括計算は逐次計算と同じ値になる（`test/realtime_intensity_series_test.dart`）。
- 開発用の Linux コンテナ（AOT）で、100 Hz・記録長 300 秒・3成分の一括計算は 1 観測点あたり 1 Hz で 6.5 ms、10 Hz で 6.9 ms だった。逐次計算の 1 Hz は 5.8 ms。

## 移植元との差分

- サンプリング周波数を引数で受け取る。移植元は 100 Hz 固定。ハイパスの係数も固定値ではなくサンプリング周波数から求める。100 Hz では移植元の係数と 1e-12 以内で一致する。
- 倍精度で計算する。移植元は単精度。
- 起動直後の安定判定（60秒経過かつ標準偏差 0.05 以下）は持たない。強震記録はトリガーの15秒前から始まり、先頭から値を出す。
- 窓の秒数を引数で変えられる。既定値は移植元と同じ60秒。
- 一括計算では計算周期を1秒より短くできる。移植元は1秒（`INTENSITY_PROCESS_SAMPLE_GROUP_SIZE` が 100）ごと。

## 検証

- 振幅特性（ハイパスを含む）は、平成8年気象庁告示第4号の計測震度の算出方法のフィルタ（周期効果・ハイカット・ローカット）に対し、
  100 Hz・200 Hz とも 0.2〜10 Hz で 3% 以内に一致する（`test/jma_intensity_filter_design_test.dart`）。
  100 Hz での比は 0.1 Hz で 0.968、15 Hz で 1.146、20 Hz で 1.379 で、10 Hz を超えると告示のフィルタより大きくなる。
- 1 Hz・100 gal の正弦波で 4.9 になる。告示のフィルタの 1 Hz の倍率 0.9964 から求めた値 4.937 と同じ階級になる。
- K-NET の記録2件で、リアルタイム震度の最大値と、告示の方法（周波数領域のフィルタ、記録全長）で求めた計測震度を比べた。
  告示の方法の値は開発時に別途計算したもの。EHM001 の 1.6 は `packages/kyoshin_waveform` のテストで確認している。

  | 記録 | リアルタイム震度の最大値 | 告示の方法 |
  | --- | --- | --- |
  | AIC001（2011-03-11 14:46） | 3.0 | 3.05（3.0） |
  | EHM001（2024-08-08 16:43） | 1.6 | 1.55（1.5） |

- 記録の先頭数秒は、フィルタの初期状態が 0 のため値が低めに出る。AIC001 では先頭1秒が -0.4 で、7秒ほどで平常時の 0.8 に達した。
